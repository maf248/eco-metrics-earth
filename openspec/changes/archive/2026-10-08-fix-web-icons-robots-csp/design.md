# Design

## Context

- Next.js merges `Metadata` across segments **shallowly**: `app/page.tsx` and `app/[category]/page.tsx` each declare their own `openGraph` and `twitter` objects (title, description, url), which replace the root layout's objects entirely. The root `openGraph.images` and `twitter.card` therefore never reach any page.
- When `twitter.images` is not set, Next fills `twitter:image` from the resolved Open Graph images.
- `next.config.ts` sets `trailingSlash: true`: extensionless routes without a trailing slash answer `308`.
- The logo SVG (`public/icons/eco-metrics-earth.svg`, mirrored by the `SiteLogoIcon` component) is full-bleed with a transparent background. As a maskable icon it gets cropped by launcher masks, and Android/iOS fill the transparency with black.
- The web build runs as `next build` with `cwd: apps/web` locally, while Vercel runs `npx nx build web --prod` from the repo root. Code that reads files through `process.cwd()` is fragile across the two.

## Goals / Non-Goals

**Goals:** social previews work on every route, PWA icons follow the manifest spec (separate `any` and `maskable` entries), iOS gets a raster apple-touch-icon, `robots.txt` is a single honest group, and the CSP stops allowlisting unused origins. Code and specs end up in agreement.

**Non-Goals:** see the proposal — no per-page OG images, no logo redesign, no further CSP tightening.

## Decisions

### D1 — Social card served by a static route handler at `/og-image.png`

`app/og-image.png/route.tsx` returns an `ImageResponse` (from `next/og`), 1200×630, with `dynamic = 'force-static'`, so it is prerendered at build and served as a static PNG. The layout: black `#000000` background (the PWA `background_color` and the site's dark default), the logo on the left, `eco-metrics earth` and the tagline on the right, and an emerald `#10b981` bottom bar (`theme_color`).

- **Why not the `opengraph-image` file convention.** It was implemented first and verified against a real build, which surfaced two defects. (1) File-based metadata only reaches segments that do not declare their own `openGraph`; `[category]/page.tsx` declares one, so category pages still had no `og:image`. (2) Next emits its URL without a trailing slash (`/opengraph-image?<hash>`), and with `trailingSlash: true` that answers `308`, which some scrapers do not follow for preview images. Next exempts paths with a file extension from the trailing-slash redirect (as with `/robots.txt`), so `/og-image.png` responds `200` directly. Route handlers for non-UI files are the documented pattern (`app/rss.xml/route.ts`).
- **Logo source:** the existing `SiteLogoIcon` component is rendered inline. Satori supports `<svg>`/`<g>`/`<path>`, and inline rendering avoids both a `process.cwd()`-relative read of `public/` (the cwd differs between local `next build` and Vercel's `nx build`) and a network fetch at build time.
- **Font:** the default font bundled with `next/og` (regular weight only). No remote font fetch, so builds stay offline-safe. _Alternative rejected:_ loading a Google Font into `ImageResponse` adds a network dependency at build for no brand gain.

### D2 — Shared social metadata helper (`lib/socialMetadata.ts`)

Next merges `metadata` shallowly, so every segment that declares `openGraph`/`twitter` must carry the shared fields itself. `buildOpenGraph(fields)` returns `{ type: 'website', siteName, images: [OG_IMAGE], ...fields }` and `buildTwitter(fields)` returns `{ card: 'summary_large_image', ...fields }`. The layout, `page.tsx` and `[category]/page.tsx` use them. `OG_IMAGE` (url, width, height, alt, type) is the single source shared with the route handler. `twitter.images` is left unset: Next fills it from the resolved Open Graph images. This also fixes a pre-existing gap with the same root cause: `og:type` and `og:site_name` were missing on the home and category pages.

### D3 — Icon assets generated by the existing script

`scripts/generate-pwa-icons.mjs` produces:

| File                    | Size    | Background  | Logo scale | Manifest purpose           |
| ----------------------- | ------- | ----------- | ---------- | -------------------------- |
| `icon-192.png`          | 192×192 | transparent | 100%       | `any`                      |
| `icon-512.png`          | 512×512 | transparent | 100%       | `any`                      |
| `icon-maskable-192.png` | 192×192 | `#000000`   | 56%        | `maskable`                 |
| `icon-maskable-512.png` | 512×512 | `#000000`   | 56%        | `maskable`                 |
| `apple-touch-icon.png`  | 180×180 | `#000000`   | 80%        | — (`metadata.icons.apple`) |

56% is the largest square that fits entirely inside the 80%-diameter safe-zone circle (0.8 / √2 ≈ 0.566). This guarantees that no mask shape crops any part of the logo, whatever the artwork's corners contain. iOS applies a rounded-rectangle mask with little cropping, so the apple icon keeps a 10% margin per side. Maskable and apple PNGs are flattened (no alpha channel). The SVG manifest entry becomes `purpose: 'any'`. Next's types accept only a single purpose per entry, which is also why the old spec's `'any maskable'` could never be implemented.

### D4 — robots.txt: one group

`rules: { userAgent: '*', allow: '/' }` plus the sitemap. The `/api/` disallow is removed because the web domain has no `/api/` routes or rewrites (verified: no `app/api/` segment, no `rewrites()` in `next.config.ts`).

### D5 — CSP

`style-src 'self' 'unsafe-inline'` and `font-src 'self'`. Nothing in `apps/web` loads Google Fonts or uses `next/font` (`next/font` self-hosts anyway).

## Risks / Trade-offs

- **Satori SVG support is a subset.** If a logo path fails to render, the card would show a blank area. _Mitigation:_ the generated PNG was inspected visually during implementation, and the E2E covers the route returning a valid PNG.
- **Social networks cache previews.** Previously shared links keep their old (empty) preview until the platform re-scrapes. This is outside our control and acceptable.
- **A future page could bypass the helper.** A page that declares `openGraph`/`twitter` without `buildOpenGraph`/`buildTwitter` would silently lose the image and card. _Mitigation:_ the helper's doc comment explains why it exists, and the E2E asserts the social tags on the home page and a category page.

## Migration Plan

No migration. Deployment is a normal web release, and rollback is a revert.

## Open Questions

None. Image style, icon background (`#000000`) and the robots decision were confirmed with the user.
