# Tasks: Sentry error tracking

Spec references use the capability name and the requirement or scenario title. Tasks 1 to 6 are for the user, never for the coder: the token must never be pasted in chat, a file or a commit. The coder starts at task 7 and may do so in parallel with the user's steps, because everything is inert until the variables exist. Only the Vercel web build needs a Sentry token; the API needs none.

## A. Manual steps for the user (Sentry, GitHub, Vercel)

- [ ] 1. In Sentry (EU, org `eco-metrics-earth`) open **Settings → Developer Settings → Organization Tokens → Create New Token**, name it `eco-metrics-ci` and copy the `sntrys_...` value once (Sentry shows it only at creation). An Organization Auth Token gets the CI scopes (release creation and source map upload) automatically; no extra scopes to tick. If the UI offers a personal token instead, it needs only `project:releases` and `org:read`. (error-tracking-runbook: Token and storage steps are documented)
- [ ] 2. Vercel: project **Settings → Environment Variables**, add `SENTRY_AUTH_TOKEN` (the token) for **Production** and **Preview**, toggle **Sensitive** on, leave Development unchecked. No GitHub secret is needed.
- [ ] 3. Vercel: add `NEXT_PUBLIC_SENTRY_DSN` with the `eco-metrics-web` DSN (copy it from the project's **Client Keys (DSN)** page; it has the shape `https://<public-key>@<org-id>.ingest.de.sentry.io/<project-id>`) for **Production** and **Preview** (not Sensitive: it is public and is inlined in the browser bundle). Leave Development unchecked.
- [ ] 4. GitHub: **Settings → Secrets and variables → Actions → Variables → New repository variable**, name `SENTRY_DSN_API`, value the `eco-metrics-api` DSN (from that project's **Client Keys (DSN)** page). One value serves both Cloud Run services.
- [ ] 5. Do 1 to 4 before merging the implementation to `develop`, or the first deploys run with Sentry disabled (and without web source maps); after adding them later, redeploy (Vercel applies variables only to new builds; the API needs a new deploy).
- [ ] 6. After the first deploys, follow `docs/deploy/sentry.md` (written by task 24) to create the alert rules, the client-key rate limits and the uptime monitor in the Sentry UI.
