# Proposal: Upgrade NX 22 → 23

## Goals

- **Eliminate the NX-toolchain share of the `npm audit` vulnerabilities.** The audit baseline (verified 10 Sep 2026) is **76 vulnerabilities (5 critical, 56 high, 13 moderate, 2 low)**. The largest block lives in transitives of the NX toolchain: advisories against the `@nx/*` packages themselves (affecting all 22.x up to 22.7.6), the `@module-federation/*` subtree, and vulnerable pins inside `nx@22.7.2` (`axios 1.16.0`, `tmp 0.2.4`, `yaml 2.8.0`, `form-data 4.0.5`, `brace-expansion 5.0.5`) and `@nx/webpack@22.7.2` (`webpack-dev-server ^5.2.1`, `less <4.6.0`). `npm audit` itself reports `@nx/webpack@23.2.1` as the fix for the `smol-toml` and `brace-expansion` advisories, and `@nx/webpack@23.2.1` drops `webpack-dev-server` from its dependency tree entirely.
- **Stay on a supported, current NX major** (NX 23 is the "Current" release line; NX 22 is LTS) before the P1 provider modules and D2 (NestJS 12) are built on top — avoids stacking new code on top of a pending migration.
- **Keep every validation gate green with zero errors and zero warnings** — `npm run lint`, `npm run build`, `npm run test` (279 unit tests), full Playwright E2E suite (49 specs), and warning-free builds (NX 23 deprecation warnings are resolved, not silenced).

## Non-Goals

- **No NestJS 11 → 12 upgrade** — that is D2, a separate change to be speced after this one. Patch bumps of `@nestjs/swagger` / `@nestjs/platform-express` that would clear their audit advisories are also deferred to D2.
- **No Next.js, React, or TypeScript upgrades** — Next stays `16.3.4`, React stays `19.3.0`, TypeScript stays `5.9.3`. Any optional migration in `migrations.json` that bumps these is pruned before running.
- **No new features or product behavior changes** — the 12 category pages, BFF, and shared package behave identically before and after.
- **No refactors beyond what the migration requires** — only changes generated by `nx migrate` migrations plus the one manual config fix demanded by NX 23 deprecations (`apps/web/next.config.ts`).
- **No changes to application source code** — `src/` directories are untouched. The only app-level file modified is `apps/web/next.config.ts` (build config), required because NX 23 deprecates the `withNx`/`composePlugins` helpers it uses.
- **No fixing of remaining non-NX vulnerabilities** — advisories outside the NX subtree are out of scope: `multer`/`js-yaml` under `@nestjs/*` (→ D2), `tar`/`sigstore`/npm internals under `semantic-release` and `shell-quote` under `concurrently` (→ D4), and `postcss` (direct dep, patch fix available — flagged as an open question for the user).
- **No adoption of new NX 23 capabilities** — Nx Cloud, Nx Agents, task sandboxing, shell tab-completion, agentic migrate, and the `migrate` config section in `nx.json` are not enabled or configured by this change.
- **No CI workflow changes** — `.github/workflows/ci.yml` already runs Node 24 and `npm ci`; it requires no edits.

## Impact

| Area | Change |
|------|--------|
| Root `package.json` | 10 NX-family pins move from `22.7.x` to `23.2.1` exact: `nx`, `@nx/devkit`, `@nx/jest`, `@nx/js`, `@nx/nest`, `@nx/next`, `@nx/node`, `@nx/playwright`, `@nx/react`, `@nx/webpack` |
| `package-lock.json` | Regenerated — the `@nx/*`, `@module-federation/*`, `webpack-dev-server`, `svgo`, `undici`, `ws`, `adm-zip` transitive tree is replaced |
| `nx.json` | Possibly touched by migrations (plugin options / generators defaults); reviewed, no manual redesign |
| `migrations.json` | Created by `nx migrate`, reviewed and pruned, deleted after the migration completes |
| `apps/web/next.config.ts` | Remove deprecated `withNx`/`composePlugins` helpers; add explicit `transpilePackages: ['@eco-metrics/shared']`; all other config (CSP headers, trailing slash, bundle analyzer) unchanged |
| `apps/api/webpack.config.js` | **No change** — already uses the modern `NxAppWebpackPlugin` class (not a deprecated helper) |
| `README.md` | Tech stack table: NX `22.7.2` → `23.2.1` |
| `AGENTS.md` | NX version mentions (`NX v22` → `NX v23`) |
| `ROADMAP.md` | D1 status → completed; I01 audit numbers updated with post-migration counts |

No `project.json` files exist in this workspace — all targets are inferred via the `nx.json` plugins array (`@nx/js/typescript`, `@nx/jest/plugin`, `@nx/next/plugin`, `@nx/eslint/plugin`, `@nx/webpack/plugin`, `@nx/playwright/plugin`) plus `nx.targets` blocks inside the per-project `package.json` files. The inference-plugin approach is the recommended pattern in NX 23 (executors are the deprecated path), so the workspace's architecture is already aligned with the target version.
