# Proposal: Streamline pre-push E2E — slim hook + deterministic E2E readiness

## Goals

- **Make `git push` fast and deterministic again.** On 11 Sep 2026 a single push to `develop` took **4 attempts**, chained by three causes: (1) `.husky/pre-push` runs the FULL Playwright suite (`npx nx e2e web` — 49 specs, 5 browser projects, ~10 min fresh, not NX-cached, silent output) on every push, even docs-only ones; (2) git opens the SSH connection before the hook runs, and GitHub kills the idle connection during the ~10 min hook → `Connection closed by remote host` after the hook finishes; (3) the pre-existing ROADMAP I17 flake — the Playwright `webServer` config waits only for `:3000`, so API-dependent specs (`e2e/api-health.spec.ts`, 10 `@smoke` specs) can start before `nx serve api` listens on `:3001` → `ECONNREFUSED :3001` on fresh runs.
- **Meta 1 — take E2E out of the local pre-push hook.** The hook keeps: the direct-push-to-`main` block and `npx nx affected --target=test --base=origin/develop` (fast, NX-cached). This is safe because validation now rests on three layers: **the SDD flow is the primary guarantor** (@tester runs unit tests + E2E at the Validate step when the change warrants it — Meta 3), **CI is the unconditional safety net** (verified in `.github/workflows/ci.yml`: `on: push: branches: ['**']` + a final `npm run e2e` step — full suite, not affected-based — plus every PR to `main`), and **the hook is the fast gate** (main-block + NX-cached affected tests). A broken E2E cannot reach production: a `develop` push is caught by CI minutes later, before any PR can merge.
- **Meta 2 — fix ROADMAP I17 with a readiness wrapper.** `npx nx e2e web` (local or CI, fresh) becomes deterministic: no spec starts before BOTH servers answer. A wrapper script (`apps/web/e2e/run-dev-servers.ts`) starts the API first (adopting it if already running), waits for `http://localhost:3001/api/v1/health`, and only then starts the web dev server — so Playwright's readiness signal (`:3000`) responding **implies** the API was ready first. The wrapper also kills the complete process trees on shutdown (including the `next-server` worker that survives its parent — the orphan source documented in AGENTS.md), validated empirically on 11 Sep 2026.
- **Meta 3 — make the SDD flow the explicit validation guarantor.** With E2E out of the hook, the Validate step carries the weight: `@tester`'s Verify step runs the unit suites AND E2E (the current "run the tests or provide the exact command" escape hatch is removed); `@spec-writer` includes E2E tasks in `tasks.md` discretionally by change type (user-facing / behavioral / significant → include; small or no-behavior → skip; when in doubt → ask the user — same pattern as the orchestrator's spec-vs-direct triage). AGENTS.md and CLAUDE.md each get one line naming the gate: lint + build + unit tests, plus E2E when the change warrants it per the spec.
- **Keep every validation gate green with zero errors and zero warnings** — `npm run lint`, `npm run build`, `npm run test` (283 unit tests), coverage thresholds intact, plus the empirical E2E gates: two consecutive fresh `npx nx e2e web` runs, fully green, with both ports verified free after each run.
- **Sync the documentation this change makes stale:** AGENTS.md — Validate step gate line, pre-PR checklist gains `npm run e2e`, and the "Push workflow" playbook rewritten condensed (~4 lines; the "10-min silent hook", SSH-timeout-during-hook, and I17-workaround items are obsolete and removed); CLAUDE.md — Validation step mirrors the same gate line; ROADMAP.md — I17 resolved and removed; I18 renumbered → I17 per the doc's continuous-sequence rule.

## Non-Goals

- **No CI workflow changes** — `.github/workflows/ci.yml` is untouched. It already runs lint → typecheck → build → test → full E2E on every push to every branch and on PRs to `main`; that unconditional net is precisely what makes the local hook slim-down safe. Making CI affected-based or otherwise reduced is explicitly out of scope.
- **No switch of E2E to production builds** (`nx build web` + `next start`, built API) — evaluated in design.md and rejected for this change: it changes the environment profile the suite tests (dev vs prod) and adds build time to every run. It remains a possible future follow-up, not part of this change.
- **No changes to the E2E specs themselves** — `apps/web/e2e/*.spec.ts` files, their tags, and their assertions are untouched. The fix is entirely in the server-bring-up layer.
- **No `implicitDependencies: ["api"]` declaration on the web project** — evaluated as the mitigation for the affected-e2e blind spot and rejected (degrades affected precision for ALL web targets); see design.md "Meta 1 — decision".
- **No fixing of the renumbered I17 (ex-I18) `WaterFootprintService` `console.warn`** — this change only renumbers the ROADMAP entry; the warning fix stays its own backlog item.
- **No dependency changes** — no new packages, no version bumps, no `package.json` edits of any kind. The wrapper uses only Node built-ins (`node:child_process`, `node:http`-free fetch polling) and the existing `npx nx` commands.
- **No changes to root `package.json` scripts** — `dev`, `e2e`, `test`, etc. stay exactly as they are. The wrapper replaces the webServer `command` inside `playwright.config.ts`, not the npm scripts.
- **No nx.json / targetDefaults / caching changes** — the E2E target's caching behavior is out of scope.
- **No `opencode.json` changes** — the two agent edits (`.opencode/agents/tester.md`, `.opencode/agents/spec-writer.md`) touch prompt behavior only; models, permissions, and every other `.opencode/**` file stay untouched.
- **No commits, pushes, or PRs** — per explicit user decision, the implementation stays in the working tree; the user validates manually (fresh E2E runs, hook dry-validation) before authorizing any commit. This proposal intentionally contains no commit/push tasks.

## Impact

| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `.husky/pre-push`                          | The `npx nx e2e web` line is **removed**. The hook keeps: (a) the direct-push-to-`main` block, (b) `npx nx affected --target=test --base=origin/develop`. A short comment documents that E2E intentionally lives in CI (`.github/workflows/ci.yml` runs it on every push) and how to run it locally (`npm run e2e`).                                                                                                                                                                                                                       |
| `apps/web/e2e/readiness.ts`                | **New file** — pure readiness-polling module: `waitForUrl(url, options)` with injectable `fetchImpl`, `timeoutMs`, and `intervalMs`; resolves on HTTP 200, retries on connection errors, rejects with a clear message on timeout. No side effects on import; fully unit-tested.                                                                                                                                                                                                                                                            |
| `apps/web/e2e/run-dev-servers.ts`          | **New file** — the webServer entry script: quick pre-check of `:3001/api/v1/health` (adopt if already up), otherwise spawn `npx nx serve api` and poll to readiness; then spawn `npx nx dev web`; stay alive until signaled. On SIGTERM/SIGINT/SIGHUP (and best-effort on `exit`): kill each spawned child's complete process tree via descendant walk (SIGTERM → grace period → SIGKILL) — empirically proven to take down the detached `next dev` session and its `next-server` worker. Adopted (pre-existing) servers are never killed. |
