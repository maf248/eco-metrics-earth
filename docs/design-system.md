# Design System

## Purpose

This document is the single source of truth for presentation decisions in **eco-metrics earth** — theming, typography, spacing, color palettes, visualization heuristics, and accessibility conventions. It is read by `@coder` before implementing a UI-bearing change, and by `@reviewer` when auditing one. It is extended (not replaced) as new decisions are made.

**This document outranks an agent's general knowledge.** Where it states a fact about this codebase, that fact wins over the usual answer for a React/Tailwind project. Where it marks something pending, that is an open question — not an invitation to decide it in passing. Library candidates and the technical traps behind them live in `docs/technical/libraries.md`; that document is research, not decisions.

## Theme Rules

- Dark mode is class-based: `apps/web/src/app/globals.css` declares `@custom-variant dark (&:where(.dark, .dark *))`, and `ThemeProvider`/a blocking inline script toggle the `dark` class on `<html>`.
- `apps/web` uses Next.js 16 (App Router), React 19, and Tailwind CSS v4. Every UI color is a **semantic color token** (see [Color Tokens](#color-tokens)): a raw custom property declared in `globals.css` with its light value on `:root` and its dark value under `.dark`, exposed through `@theme inline` as one utility per role. Components write `bg-surface text-fg`, never `bg-white dark:bg-black`.
- Pages and components (`src/app/**`, `src/components/**`) MUST NOT use Tailwind palette colors (`white`, `black`, `gray-500`, …) or arbitrary color values (`bg-[#…]`) — with or without `dark:` — except the documented exceptions below. `apps/web/__tests__/designTokens.test.ts` fails the unit suite on any violation, on a token missing its dark value, and on a token nobody uses.
- Code outside Tailwind that renders to the DOM (inline SVG styles) reads the raw variables, e.g. `fill: var(--accent)`; they switch with the theme on their own. ECharts cannot: charts and maps receive token values through the theme adapter (see [Chart rules](#chart-rules)).
- Eco-category icon components in `apps/web/src/components/icons/` are intentionally multicolor and use hardcoded fill values as part of each category's visual identity; per the `light-mode-styling` capability, they MUST NOT be recolored or tinted per theme. Any contrast fix must add separation (e.g. drop-shadow, border, background highlight) without altering the SVG's own colors.
- Brand raster assets use black `#000000` (the manifest `background_color`) as their opaque background: the maskable PWA icons and the apple-touch icon (logo centered, generated by `scripts/generate-pwa-icons.mjs`), and the 1200×630 social card served at `/og-image.png`, which adds the site name, tagline, a subtle `Explore the data →` call to action (emerald accent, secondary in size to the site name) and an emerald `#10b981` (`theme_color`) bottom bar. Every page's `openGraph`/`twitter` metadata is built with `apps/web/src/lib/socialMetadata.ts`, so the card is never lost to Next's shallow metadata merge.
- Category icons render with a subtle drop-shadow in light mode and a faint white glow in dark mode; large icons also sit inside a rounded container with a neutral background highlight that matches the inactive nav pills (`bg-well`). SVG fills remain unchanged. The shadow/glow pair is tokenized per size as `drop-shadow-icon-{xs,sm,lg,xl}`.

## Color Tokens

Declared in `apps/web/src/app/globals.css`. Values are Tailwind 4.3.3 palette entries written in `oklch()` (`white/N` = white at N% opacity); the two `nav-surface` values are exact conversions of `#eaecef` / `#1a1a1a`. Utility = the token name after a color prefix: `bg-surface`, `text-fg-muted`, `border-line`, `ring-focus-ring`, `ring-offset-focus-offset`, `from-nav-surface`; opacity modifiers work (`bg-surface/95`).

#### Warning tokens: contrast

Amber family, deliberately not an error red: a degraded provider is not a failure of the site. Ratios are WCAG relative-luminance contrast, computed from the `oklch()` values above (sRGB, no gamut clipping needed). Thresholds: text >= 4.5:1 on its own surface, icon >= 3:1 on every surface it sits on.

| Pair                                                | Light  | Dark    |
| --------------------------------------------------- | ------ | ------- |
| `warning-fg` on `warning-surface` (notice text)     | 8.77:1 | 13.47:1 |
| `warning-fg` on `surface`                           | 9.09:1 | 18.87:1 |
| `warning-fg` on `surface-raised` (unavailable icon) | 9.09:1 | 13.19:1 |

`warning-line` is a decorative border (1.39:1 on `warning-surface` in light, 2.10:1 in dark): the notice never relies on it, the icon and the text carry the meaning.

### Documented exceptions

- **Theme toggle lamp** (`ThemeToggle.tsx`): `text-amber-400` with an amber glow in light mode, `dark:text-gray-400 dark:drop-shadow-none` in dark mode. It is a lit/unlit state indicator rather than a role color, and the `theme-toggle` capability defines it in terms of `dark:` variants. It is the only allowlisted entry in `designTokens.test.ts`.

### Adding or changing a token

Add the light value to `:root`, the dark value to `.dark`, the `@theme inline` mapping, a consumer, and a row in the table above — in the same change. The guard test enforces the first four; the table is kept in sync by review.

## Color Palettes

Chart colors are tokens like any other color: light value on `:root`, dark value under `.dark`, in `globals.css`. There are two palettes, both read by name by the theme adapter and not mapped in `@theme inline`: the categorical `--chart-1…8` (series with no meaning of their own) and the semantic energy mix `--energy-*` (below). The first change that renders a chart adds the categorical tokens; the energy mix palette (electricity sources) is separate and semantic; the sequential ramp `--chart-seq-1…5` with its no-data fill `--chart-no-data` was added by the world map, and the good-is-high ramp `--chart-seq-good-1…5` by the waste map, and the divergent palette stays pending. The eight categorical tokens (`--chart-1` … `--chart-8`) are declared with the values below and are not mapped in `@theme inline`: the theme adapter (`components/charts/chartTheme.ts`) reads them by name, and `designTokens.test.ts` recognises them as used by comparing the declared `--chart-*` names with `CHART_COLOR_TOKENS`. Unlike the UI tokens they are written in hex, the form they were validated in; the theme adapter resolves any CSS color format. Both palettes were validated against the real surfaces (white in light mode, black in dark mode) with a palette validator that checks OKLCH lightness band and chroma floor, adjacent-pair separation as OKLab ΔE×100 under protanopia/deuteranopia/tritanopia simulation (target ≥ 8) and unsimulated (floor ≥ 15), and WCAG contrast against the surface.

### Sequential (light / dark)

Five classes, low → high, plus a no-data fill. Used by choropleth maps (the CO2 per-capita world map and, with the green ramp below, the waste & recycling map) through the theme adapter's `visualMap.inRange.color` and `map.itemStyle.areaColor`; the HTML legend (`MapLegend`) paints its swatches from the same tokens. Like the categorical palette they are hex, read by name and not mapped in `@theme inline` (`CHART_SEQUENTIAL_TOKENS`, `CHART_NO_DATA_TOKEN` in `chartTokens.ts`).

| Token           | Light     | Dark      |
| --------------- | --------- | --------- |
| `chart-seq-1`   | `#f5af20` | `#fed25f` |
| `chart-seq-2`   | `#ec8300` | `#f9a129` |
| `chart-seq-3`   | `#de5300` | `#f16a00` |
| `chart-seq-4`   | `#c1291b` | `#da3b21` |
| `chart-seq-5`   | `#8a161b` | `#b32322` |
| `chart-no-data` | `#e5e5e5` | `#262626` |

- **Yellow → red, not one hue.** Emissions read as heat, and the user chose this ramp over a single-hue blue in the map spike. Lightness falls monotonically from class 1 to class 5 in both themes, with every adjacent gap ≥ 0.06 OKLCH L (validator, ordinal mode), so the order survives colour-vision deficiency and greyscale. In dark mode the ramp keeps the same direction (bright yellow is low): the high classes stay saturated reds instead of sinking into the black surface.
- **Recorded exceptions.** Hue spread is 53° (light) / 61° (dark), above the 40° one-hue guideline: accepted on purpose for the heat reading. In light mode `chart-seq-1` sits at 1.90:1 against white (below the 2:1 floor); the class is still separated from the surface by the region outlines (`line-strong`), the legend and the ranking table, which carries every value as text.
- **No data** is a neutral grey, never a ramp step: separation from `chart-seq-1` is ΔE×100 20.1 light / 62.8 dark unsimulated and ≥ 17.7 under every CVD simulation (floor 15). Its low contrast against the surface (1.26:1 / 1.39:1) is fine for "nothing here"; the legend names it ("No data"), and such regions are inert (no hover, tooltip or selection).
- **Used by two maps.** The CO2 per-capita map, and the waste map for "uncollected" and "kg per person per day" (a share where more is worse, and a neutral quantity); its recycling measures use the green ramp below.
- **Fixed class breaks, not quantiles.** The breaks are part of the encoding of each map (CO2: < 1, 1–3, 3–6, 6–10, ≥ 10 t per person), so a colour means the same value in every year the slider shows.

#### Good-is-high ramp (`chart-seq-good-1…5`)

A second five-class ramp for a share where **more is better** (the waste map's "recycled" and "recycled or composted"), so the best recyclers are not painted in the heat ramp's alarm red. The waste map therefore uses **both**: green for the two recycling measures, the heat ramp above for "uncollected" and "kg per person". `ChoroplethMap`, `MapLegend` and the chart theme take a `ramp` (`good` | `heat`; `CHART_RAMP_TOKENS`) and the map follows the selected measure. Same rules as the heat ramp: hex, read by name, declared on `:root` and `.dark`, not mapped in `@theme inline`, one no-data fill shared by both.

| ------------------ | --------- | --------- |
| `chart-seq-good-1` | `#58c69b` | `#94f6cc` |
| `chart-seq-good-2` | `#36a980` | `#5ed8a9` |

- **One hue (165°, spread 1° light / 0° dark), lightness falling monotonically:** OKLCH L 0.751 / 0.660 / 0.569 / 0.480 / 0.389 (light) and 0.901 / 0.800 / 0.699 / 0.601 / 0.499 (dark): every adjacent gap ≥ 0.09, above the 0.06 minimum (validator, ordinal mode: all four checks PASS in both themes).

## Typography

- Fonts and type scale follow Tailwind CSS v4's default typography utilities as currently used across `apps/web/src/app/**` and `apps/web/src/components/**`.
- No custom `@theme` font tokens are defined (the `@theme inline` block holds only color and icon-shadow tokens).

## Spacing

- Spacing follows Tailwind CSS v4's default spacing scale (the `4px`-based `space-*`/`p-*`/`m-*`/`gap-*` utilities) as currently used across the codebase. No custom spacing tokens are defined.

## Layout

- Desktop (`lg+`) sidebar (`Navbar.tsx`): fixed width `lg:w-76` (304px), matched by `lg:pl-76` on the page content offset (`layout.tsx`) — the two must move in lockstep.
- Safe areas: the viewport is `viewport-fit=cover`, so the page may draw under the system bars (Android gesture bar, iOS home indicator, landscape notch; the status bar where a browser overlays it) instead of leaving a strip in the browser or PWA color below the bottom nav. The fixed chrome pads itself by the insets with the `globals.css` utilities: the mobile bottom nav is `h-bottom-nav` (`h-20` plus the bottom inset) with `pb-safe`, so its own background fills the gesture-bar area; the content wrapper clears it with `pb-bottom-nav`; the mobile header is `h-header` (`h-14` plus the top inset) with `pt-safe`, and pages clear it with `pt-header` (never a bare `pt-14`); `<body>`, the header and the nav get `px-safe`, and the theme toggle `top-toggle` and `mr-safe`. Every inset is 0 where there is no such bar.
- Desktop nav item rows (`NavLink.tsx`): row density `lg:py-2`, chosen so all 12 `NAV_ITEMS` fit within a typical desktop viewport height (~700px+) without scrolling.
- Vertical scroll affordance (`NavScrollContainer.tsx`): on desktop, top/bottom gradient overlays signal hidden nav items above/below the visible area, mirroring the existing horizontal affordance used by the mobile bottom bar. Both reuse the same `nav-surface` token as their horizontal counterparts (`from-nav-surface`), oriented vertically (`bg-linear-to-b` / `bg-linear-to-t`).

- Site footer (`Footer.tsx`): rendered inside the content wrapper right after the root `<main>` (`pb-bottom-nav lg:pb-safe lg:pl-76`), in normal document flow, so it inherits the mobile bottom-nav clearance and the desktop sidebar offset. A single `<footer>` (`contentinfo`, outside `<main>`) in the terminal style of the brand: the site logo with `~ eco-metrics.earth` in mono accent, a one-line tagline, one link shown as `$ cd data-sources/` (decorative `aria-hidden` prompt, accessible name "Data sources", `LINK_CLASS_NAME`), and a muted copyright/signature line under a `border-line-subtle` rule. Two columns from `sm`, stacked on mobile; tokens only (`border-line`, `text-accent`, `text-fg-secondary`, `text-fg-muted`). Mains are `min-h-screen`, so the footer sits at the end of the scroll, not in the first viewport.

### Page titles

- The `<h1>` of the home, every category page, the data sources page and the not-found and error pages shares `PAGE_TITLE_CLASS_NAME` (`lib/pageTitleClassName.ts`): the brand's terminal style, `font-mono tracking-tight text-accent`, at `text-4xl font-bold` with `text-balance`. It is the only heading in `accent`: `<h2>`/`<h3>` stay `text-fg`.

### Home page

- Server-rendered and static (`app/page.tsx`): all content is in the HTML and there is no BFF request, so `next build` never depends on the API.
- Hero, centered: the site logo in the same `w-24 h-24 rounded-2xl bg-well` container as a category header icon, one `<h1>` with the value proposition (the footer tagline) in the page-title style (below) that types itself in through `TypewriterText`, the shared site description in `fg-secondary`, and one primary button that scrolls to the topics (`#topics`, whose section carries `scroll-mt-header`, the `globals.css` utility that clears the fixed mobile header, top inset included). The button is a `SmoothAnchor`: a plain `<a href="#…">` that sets `anchor-scrolling` on `<html>` for the length of its own scroll, which `globals.css` turns into `scroll-behavior: smooth` only without a reduced-motion preference. Never set smooth scrolling site-wide: it animates the browser's scroll restoration on back and forward.
- `TypewriterText` is server-rendered and CSS-only: every character is in the HTML at its final place and only hidden until its turn (45 ms per character), the cursor (`▋`) sits `0.2em` after the text: while typing it is drawn out of flow after the last character, and the closing one, which holds its place from the start, blinks at the end with `animate-cursor-blink`, so nothing shifts and nothing waits for JavaScript. Its parent names itself with `aria-label` and the characters are `aria-hidden`. With reduced motion the text and a steady cursor show at once. Use it for one headline per page at most.
- Primary button with body-size text: `bg-accent-solid-strong text-on-accent`, with `hover:underline`. White on `accent-solid` is 3.65:1, below the 4.5:1 that text under 18.66 px bold needs, so `accent-solid` as a button background is only for large bold labels.
- Topics: an `<h2>` and a `<ul>` grid, one column on mobile (cards stack and scroll with the page) and two from `sm`. One card per category with live data (`LIVE_CATEGORIES` in `lib/liveCategories.ts`, navigation order); placeholder categories are never listed. No carousel: every card is in the HTML and visible without interaction.
- Card: `surface-card` with a `line-strong` border and `rounded-2xl`; the category icon in a `h-14 w-14 rounded-xl bg-well` container next to an `<h3>` with the keyword-bearing title (`getCategoryMetadataTitle`), one sentence in `fg-body` (`LIVE_CATEGORY_SUMMARIES`, at most 120 characters) and a single underlined `accent` link "Explore <category> →" (the arrow is `aria-hidden`). The link's `::after` covers the card, so the whole card is one target with one accessible name; the card shows the focus ring through `has-focus-visible` and `hover:bg-hover`.
- A closing `<h2>` section links to `/data-sources/` with `LINK_CLASS_NAME`. Provider names are not repeated there: they come from the API catalog.

### Source attribution

- `SourceAttribution` is the single "<publisher link> (<license>)" fragment for any `DataSourcePublisher`-shaped value; callers add their own lead-in ("via", "Republished by", "Some values are republished by", or "Data:" on a future chart). Names and licenses always come from the API.
- Live-provider dates on `/data-sources/` are formatted in UTC (`formatUtcDate`) and wrapped in `<time dateTime>`, so server and client render identically.
- On a cited publication, "Republished by <SourceAttribution>" sits beneath the citation; per product, "via <SourceAttribution>"; under the water-footprint table, "Some values are republished by <SourceAttribution>. <All data sources link>". The citation itself is never replaced.
- Links in running text are underlined (never color alone) and share `LINK_CLASS_NAME`: `text-accent`, `hover:text-accent-hover` and the focus-ring pattern.

## Presentation Stack

- **Charts and maps: Apache ECharts 6** (Apache-2.0), SVG renderer, tree-shaken imports from `echarts/core`. Chosen for its built-in interactions (legend toggling, series focus, slice selection, animated re-sorting, map zoom/pan) and for covering charts and the choropleth with one library. Evidence and the rejected alternative are in `docs/technical/libraries.md`.
- **Map geometry:** decided with the CO2 world map. A pre-projected hybrid of Natural Earth 110m plus the small territories only 50m has (`world-atlas`, converted with `topojson-client`, projected with `d3-geo` Equal Earth), with OWID codes resolved at generation time and served as a static asset, never projected in the browser (see rule 9 below; evidence in `docs/technical/libraries.md` → Maps).
- **Country flags: `flag-icons` 7.6.0** (MIT, exact version pinned in `apps/web`), SVG flags selected through CSS classes (`<span class="fi fi-ar">`), never emoji — emoji flags render as two letters on Windows. Usage rules: the stylesheet (`flag-icons/css/flag-icons.min.css`) is imported only by `CountryFlag`, so it loads only with the components that show flags (route-level CSS bundling means it also ships with the other `[category]` pages, never with the home or data-sources pages); flags are decorative (`aria-hidden`) next to the country name; flags in long lists are rendered lazily (only rows that intersect the listbox viewport) because every rendered flag is a separate image request; World is shown with the monochrome `GlobeIcon`, not a flag; flags are images and are not subject to the color-token rules, but get a `ring-1 ring-line-strong` outline so pale flags stay visible on both surfaces. `GlobeIcon` lives in `components/`, not in `components/icons/`: that folder is the multicolor, one-per-category icon set.
- **Chart-scoped selector, no URL state.** A chart shows one entity at a time and its country selector and measure toggle live next to it as component state: no query string, path segment, history or storage, so the page keeps a single canonical URL. The whole dataset arrives with the page; interaction never fetches.
- **Country combobox** (`CountryCombobox`) follows the WAI-ARIA 1.2 editable combobox with list autocomplete. Keys: ArrowDown opens and moves (wrapping), ArrowUp moves (wrapping), Home/End jump to the first/last option only while the list is open, Enter selects, Escape closes (and, when already closed, restores the selected name), Tab and blur close and restore. Filtering ignores case and diacritics and ranks name prefix, then substring, then code prefix. Sizing: `text-base` on the input (no iOS zoom), `min-h-11` (44 px) input, clear button and options, `max-h-60` scrolling listbox, `max-w-sm`; the active option is shown by background plus a leading bar, the chosen one by a check glyph. Optional props: `placeholder` (default "Search countries"), `describedBy` (`aria-describedby` on the input), `inputRef` and `disabled`, which keeps the input focusable but read-only (`aria-disabled="true"`, `cursor-not-allowed`, `border-line`, `text-fg-muted`, no list, no clear button); the waste comparison uses it at the 10-country limit with the one-line placeholder "Limit of 10 reached" and the full sentence in the live status.
- **Removable chips** (the waste comparison's selected countries): a compact visual (`h-8` / 32 px pill, `text-sm`, `gap-1.5`, `pl-2.5`) whose remove button is drawn 28 px (`size-7`, 12 px glyph) but keeps a 44×44 px touch target through an invisible expanded hit area (`relative` + `before:absolute before:-inset-2`), so the 44 px rule holds without bulky chips. Chips sit `gap-2` apart and the hit area (8 px beyond the button, less its 2 px margin) stops about 3 px short of the neighbouring chip; it slightly covers the end of the country name, which is accepted. After a removal focus moves to the next chip's remove button, else the previous one, else the search. Focus uses `FOCUS_RING_CLASS_NAME`.
- **Anomalies are signed.** A value relative to a baseline is shown with an explicit sign and the real minus sign U+2212 (never the ASCII hyphen, which reads and wraps as a separator) in key figures, tooltips, tables and axis labels: `+0.59`, `−0.45`, `0.00` (two decimals in text, at most one on the axis), through `formatAnomaly` and `formatAnomalyAxis`, the only place a sign is produced. The sentence says "relative to the <baseline> average", which stays true for negative values.
- **A chart of values relative to a baseline draws a labelled reference line at zero** (a series `markLine`, dashed, labelled with the baseline from the payload, e.g. `1991–2020 average`). Its stroke and label colors come from the theme adapter (`referenceLine` from `fg-muted`, `referenceLabel` from `fg-secondary`), never from the option, and the value axis always includes zero.
- **A single-measure chart has no toggle.** The measure radio group exists only when there are two measures to switch (CO2: total / per capita); the global temperature explorer has the country selector alone.
- **One categorical color for the anomaly line.** Encoding the sign with color (blue/red) would be the first use of the divergent palette, which is still pending below; until it is defined and validated, the zero line carries the polarity, which also holds up for color-vision deficiency.
- **An upstream credit line is shown next to the data attribution.** When the measurements come from a producer other than the republisher and its licence asks for a credit and a disclaimer, both come from the API payload (`data.origin`) and render inside the "Data:" paragraph (the `extra` slot of `DataAttribution`), not only on `/data-sources/`.
- **Confidence band.** An interval around a line is drawn with two stacked line series (an invisible base at the lower bound and the interval width on top with a low-opacity area and no line), through `buildConfidenceBandSeries`. The band takes the main series' color from the theme palette because it shares the series name (the option never names a color; only an opacity is set), it is excluded from the tooltip, and the chart's tooltip formatter prints the interval once. Missing bounds leave a gap.
- **A reference threshold is a labelled reference line plus a sentence.** A threshold such as 1.5 °C (Paris Agreement) is drawn like the zero line (dotted so it differs from the dashed zero line without color), labelled in the chart, and explained in text: the limit refers to a long-term average, so a single year above it does not by itself breach it.
- **Below-the-fold charts render when they scroll into view** (chart rule 5): `RenderWhenVisible` serves a same-height skeleton, including in the server-rendered HTML, and mounts the lazy chart on the first intersection. The first chart of a page does not use it.
- **Each upstream origin is credited next to the chart it feeds.** `OriginCredit` renders a `DataSourceOrigin` from the API (producer, linked title, linked license, then the notice, citation and disclaimer the license asks for) inside the "Data:" paragraph; the same origins are listed on `/data-sources/` under "Data produced by".
- **Generic building blocks** for a chart page with a country selector: `CountryExplorer` (selection state, card layout, combobox; the caller supplies controls and content), `ChartPanel` (title, chart, hidden live region), `YearDataTable` (the collapsed text equivalent below) and `DataAttribution` (the "Data:" line).
- **Key figures are server-rendered text** derived from the same payload as the chart (fixed `en-US` formatting, so server and client agree), which makes them indexable and readable without JavaScript. Per-capita values that are zero or round to `0.00` read "< 0.01", never "0.00".
- **The collapsible data table (`YearDataTable`) is the text equivalent of the chart** required by chart rule 7: a `<details>` with a scrollable, keyboard-focusable region holding the selected entity's years, newest first, with an em dash for missing values.
- **Tables, key figures and controls stay HTML/React**, never drawn by ECharts: they must be indexable, reachable by screen readers and scrollable on mobile.
- **Tables are hand-rolled: no table library.** Reasons and when to reconsider are in `docs/technical/libraries.md` → Tables.

- **Composition charts (stacked area and donut).** They share one palette and source order, and every source is **always present in the option**, so colour follows the entity. Areas are **opaque** (`areaStyle.opacity: 1`; the default 0.7 would blend bands and break the validated colours), the percentage axis is fixed to **0–100** and a generation axis starts at 0 and fits the data (`max: null`, since `setOption` merges and would keep the 100). No band outlines and no hover emphasis: blurring the other bands of an opaque stack reads as missing colour. The axis tooltip lists only sources above zero; tables keep every source. The donut shows the selected entity's **latest year** (no year selector), labels hidden, deferred with `RenderWhenVisible`, with `PieChart` registered where it is used (`EPieChart` via `LazyPieEChart`).
- **A missing value is `null`, never zero:** a gap in a chart, an em dash in a table, "No data" in a tooltip. ECharts' generated `aria` description prints `null` as "NaN", so such a chart sets `aria.label.description` itself.
- **Tables follow the toggle.** The year table of a chart with a measure toggle shows the measure the chart shows, so it is always the text equivalent of what is visible; a small table that doubles as a donut legend (`EnergyLatestTable`) is visible rather than collapsed. Many columns use `YearDataTable`'s `wide` flag: header text wraps at a narrow width (`max-w-32`), so a long source name takes two lines instead of widening its column, and the table's minimum width fits the desktop card, so it scrolls only on narrower screens, never squeezing the columns.
- **`MeasureToggle`** is the one radio-group toggle between measures ("Total / Per capita", "Share (%) / Generation (TWh)"). Its optional `grid` prop lays the options out as an equal-width two-column grid below `sm` (one row from `sm` up), for a toggle with four options that would not fit a phone in one row; only the waste map uses it, each cell keeps the 44 px touch target with tighter padding and `text-sm`, an option may give a `shortLabel` shown below `sm` so it fits one line (the full `label` stays its accessible name and shows from `sm` up: "Recycled + composted" for "Recycled or composted"), and its loading skeleton reserves the resulting two-row height below `sm`.

### Navigation and skeletons

- **Skeletons mean "not here yet", on the client only.** A direct visit delivers the complete page, so the HTML never holds a fallback, except for the chart area (charts render in the browser). Do not add `loading.tsx` or a `<Suspense>` around page data: React moves a boundary over about 12.8 KB out of the visible document.
- **Known content is never a skeleton.** While a category is pending, `NavigationContent` shows its real icon and `<h1>` from shared config, then `CategoryDataSkeleton` with the blocks declared in `CATEGORY_SKELETONS`. Placeholder categories have none.
- **Shape and colour.** Blocks repeat the layout of the real content down to the first chart or list, and their text is sample copy drawn as bars (`text-transparent` over `bg-well`), so it wraps like the real text at any width and nothing above the fold moves when the page arrives. Change the page's layout or copy and update `CATEGORY_SKELETONS`: `category-navigation.spec.ts` measures the drift. Fills and strokes use only `well`, `well-active` and `hover`, on `surface-card` cards with `line-strong` borders, so they work in both themes. Animation is `motion-safe`; assistive technology gets `aria-busy` on `<main>`, and the shapes are `aria-hidden`.
- **Transition.** A 180 ms crossfade through React `<ViewTransition>`, and a thin `bg-accent-solid` bar only after 200 ms. The fixed navigation, header and theme toggle have their own `view-transition-name` above the page, or the page's snapshot would paint over them. `prefers-reduced-motion` disables both animations; without view transitions the page simply swaps.

### Degraded provider states

A provider-backed category (OWID today) can be served from a stored snapshot when its provider is down. The page decides from `meta.stale` and `meta.fetchedAt` (`lib/providerFreshness.ts`), once, on the server:

| Age of the stored data (stale only) | Shown                                      |
| ----------------------------------- | ------------------------------------------ |
| up to 7 days                        | the data, silently (no notice)             |
| over 7 and up to 30 days            | the data under the **stale notice**        |
| over 30 days, or provider `502`     | the **unavailable state** in place of data |

Defaults are `silentDays: 7` and `noticeDays: 30` (`DEFAULT_FRESHNESS_THRESHOLDS`); a category may override them with `provider.freshness` in its registry entry (`defineProviderCategoryPage`). A payload without `stale: true` is always fresh, whatever its age.

- **Stale notice** (`StaleDataNotice`): a banner directly above the section content, `warning-surface` background, `warning-line` border, `warning-fg` text and a decorative `WarningIcon`. Copy: "{Provider} is currently unreachable. Showing the copy we retrieved on {date}." with the date through `formatUtcDate` in a `<time dateTime>` and the provider from `meta.source.provider`. `role="status"` (informational, never `alert`), no controls.
- **Unavailable state** (`DataUnavailable`): replaces only the section content; the common header (icon and `<h1>`) stays and, when `meta` is known, so does the source attribution (`DataAttribution`). Neutral panel (`surface-raised`, `line-strong`, `fg`, `fg-body`) with the `WarningIcon` in `warning-fg`, not error red. `<h2>` "Data temporarily unavailable", body "We couldn't reach {Provider} to load this data. We're keeping an eye on it and it should be back soon.", and "Last retrieved from {Provider}: {date}" only when a snapshot date is known. `role="status"`, not `alert`; **no retry button**: ISR retries server-side, so a client control would only suggest an action that does nothing. The provider name comes from `meta.source.provider` when `meta` exists, otherwise from the registry entry (a `502` carries no `meta`).
- Both are tokens-only (no palette utilities) and are covered by role/semantics unit tests; axe cannot reach them in E2E because the OWID fixture server has no failure mode.

### Chart rules

1. **Colors come only from an ECharts theme built from the tokens.** ECharts parses neither `var(--x)` nor `oklch()` — a `var()` color even makes elements vanish on hover ([apache/echarts#19743](https://github.com/apache/echarts/issues/19743)) — so a shared adapter reads the tokens with `getComputedStyle`, resolves each one to `rgba()` by painting it into a 1×1 canvas and reading the pixel back, builds the ECharts theme (palette, axes, tooltip, legend, map fills) and re-applies it with `setTheme()` whenever the `dark` class on `<html>` changes. Chart options never name a color.
2. **One shared wrapper component** owns the instance: `init` with the SVG renderer, resize on a `ResizeObserver`, `dispose` on unmount. It must call `setOption` before `setTheme`: `setTheme` is a no-op until the chart holds an option. No `echarts-for-react`.
3. **Register modules where they are used.** The shared setup registers what every chart page needs (line, grid, tooltip, legend, aria, mark line, SVG renderer; bar registers where first used and the pie is registered by its own lazy entry, `EPieChart`, loaded through `LazyPieEChart`); heavier features (map, visualMap) register in the component that uses them, so they never ship to pages without them. Never the canvas renderer.
4. **Load charts lazily.** ECharts renders in the browser only. Chart components come from `lazyChart`, which imports the chunk on demand on the client and draws at once when it is already loaded (`next/dynamic` would add a Suspense boundary that delays the first chart). The page itself stays a Server Component, and `ChartSkeleton` holds the chart's height and shape (`series`, `bars`, `donut` or `map`; the `bars` height follows the number of bars through the `--bars-h` and `--bars-h-sm` custom properties its caller sets), so nothing shifts when the chart arrives. The entry animation lasts 300 ms, so a chart never feels slower than its data.
5. **Keep pages light.** A static ECharts page with line + bar + pie adds ~220 KB gzipped of JS (deferred by rule 4), and four charts at once block the main thread for ~1.8 s on a throttled mobile profile. Keep few charts per page; when a page carries several, render those below the fold only when they scroll into view (`RenderWhenVisible`). The energy sources page is the example: two charts (stacked area and donut), the donut deferred.
6. **Mobile-safe defaults** in every option: `tooltip.confine: true`, `axisLabel.hideOverlap: true`, truncated category labels, and a legend that **wraps, never scrolls** (`legend.type: 'plain'`): a scrolling legend hides entries behind tiny pager arrows. ECharts never moves a grid or a pie away from its legend, so a visible legend comes from `wrappedLegend(labels, reserve)` (`components/charts/wrappedLegend.ts`): it sits at the bottom and ECharts `media` queries on chart width reserve its rows (`grid.bottom`, or a pie box's `bottom`), from a per-character width table that is never narrower than common system fonts draw the labels. The space between the plot and the legend matches the space between the chart title and the plot (about 22 px): the area grid reserves the legend plus 17 px, and the donut's ring fills a box 14 px from the top and 17 px above the legend.
   Chart boxes come from `chartBoxClassName(variant)` (shared by the chart and its skeleton): below `sm` they bleed through the card padding to the card edges (`-mx-4 sm:mx-0`), so with the edge-to-edge cards below the plot spans the whole screen width; a series chart is `h-72 sm:h-96`, a donut `h-96` at every width.
   **Mobile layout of the data column** (`lib/cardClassNames.ts`, shared by the content, its cards and `CategoryDataSkeleton`): below `sm` the page gutter (16 px) is the only one; cards (`CARD_CLASS_NAME`) and the key-figures panel (`KEY_FIGURES_CLASS_NAME`) bleed through it to the screen edges as borderless bands, and charts and table scroll regions (`TABLE_REGION_CLASS_NAME`) bleed through the card padding (`CARD_BLEED_CLASS_NAME`) and span the card edge to edge; their focus indicator there is an outline drawn inside the edges (`-outline-offset-2`: the screen edges would clip an outer ring, and an inset ring would be covered by the sticky header and highlighted rows). Text inside a table keeps its cell padding (`px-3`; the ranking keeps 12 px after its last column). `EnergyLatestTable` is a small, always-visible table sized to fit the card, not a scroll region, and does not bleed. Text inside a card keeps the 16 px card padding. From `sm` up the column adds its own gutter and cards are rounded boxes with a `line-strong` border. At every width cards and key figures sit on `surface-card`, a tone barely off the page in both themes (`surface-raised` is lost on white in light mode and reads as a blue-gray slab in dark mode), and sticky table heads take `bg-surface-card` so they blend into the card.
7. **Accessibility:** enable `aria` (ECharts generates a description, which prints `null` as "NaN": a chart that can hold `null` sets `aria.label.description` itself), but ECharts offers no keyboard navigation inside a chart — every chart is paired with a table or a text equivalent of its data, and multi-series charts always show a legend.
8. **SEO:** a chart's SVG is not indexable content. Key figures go in server-rendered text, plus the data table and structured data where it fits. A page whose content is a dataset declares it once as a schema.org `Dataset` in JSON-LD (rendered with `JsonLd`, built from the page's own payload), never one block per chart.
9. **Maps:** the world geometry is projected once, at build time (`npm run geo:world` → `scripts/generate-world-geometry.mjs` → `apps/web/public/geo/world-countries.json`), not in the browser: Natural Earth 110m plus the 63 small territories only 50m has (≈ 50 KB gzipped, 239 regions), Antarctica removed, Equal Earth through `d3-geo-projection`'s `geoProject` (it cuts the antimeridian, so Russia and Fiji do not smear), y negated for ECharts. Each feature carries a unique `key` (the OWID entity code, or `region:<name>` for the few regions without one), and the series matches data by it (`nameProperty: 'key'`): every region gets an item, and a region without a value is `silent`, with emphasis and tooltip off. `lib/worldGeometry.ts` fetches and registers it once per page load, through the lazy map entry (`EMapChart`): `registerMap` fails until the map chart is registered, and `echartsSetup` alone may already be loaded by a line chart. Set `aspectScale: 1` and `showLegendSymbol: false`. **ECharts stretches a map to a box with all four of `left`, `right`, `top`, `bottom` set**, so the container must have the map's own aspect ratio (`aspect` in the asset, 2.238; the `map` variant of `chartBoxClassName`/`ChartSkeleton`, `aspect-2238/1000`) — the asset test fails if the two drift apart.
10. **Map interaction and companions** (`ChoroplethMap`, `MapLegend`, `YearSlider`):
    - Zoom and drag are on (`roam`, scale 1–12), and the initial view is the whole world. Wider screens get one vertical control group at the bottom left (zoom in, zoom out, reset; SVG icons, dividers between buttons). Below `sm` there are no zoom buttons (pinch and drag), only a small "Reset view" button that appears after the view moves and hides after a reset.
    - Hover and selection keep the region's class fill and draw a stronger `fg` outline (theme `map.emphasis`/`map.select` with `areaColor: null`); ECharts' default yellow fill would hide the value being pointed at. One region at a time is selected (`selectedMode: 'single'`); the selection is shared with the companion table.
    - The legend is HTML, under the map: a small fixed-width swatch per class (`h-2.5 w-7`) with its label underneath, then "No data", centered and wrapping. The ECharts `visualMap` is hidden.
    - The year is a native range input: it defaults to the latest year, a bubble (`accent-solid-strong`, `aria-hidden`: the input announces its own value) rides the thumb, and a small scale below labels both ends plus round years at least 15 % of the span away from them.
    - A map is never alone: a ranking table of the same year carries every value as text, collapsed under "View data table" like every data table (keyboard-focusable scroll region, country names as toggle buttons with `aria-pressed` sharing the map selection, the selected row highlighted and scrolled into view inside the region; the CO2 ranking also marks it with `aria-current`). Each value column header is a sort button (the active one reverses the order, another one sorts by itself, highest first; `aria-sort` on the active cell); ranks are competition ranks by the sort measure and do not change with the order. Below `sm` the region spans the card edge to edge like a chart and cells tighten, so four columns with flags fit at 360 px; the rank header reads "#".
    - The map skeleton is the land outline in the map's own frame: `well-active` masked by `apps/web/public/geo/world-silhouette.svg` (generated with the geometry, ~3 KB gzipped), with no plot box, as the map has none, so the placeholder has the shape and position of the map that replaces it. It is a static file used as a CSS mask, not JavaScript: `ChartSkeleton` ships with every chart page and the client navigation, which must not carry a CO2-only outline.
11. **Unit tests (jsdom):** `echarts` and `zrender` ship as ESM only, so `jest.config.cjs` is an async function that adds both to the `transformIgnorePatterns` allowlist `next/jest` generates; jsdom has no canvas, which ECharts uses to measure label text even under the SVG renderer, so `jest.setup.ts` injects an approximate `measureText` through zrender's platform module (imported alone, so tests that render no chart stay fast); the token adapter needs a stubbed `HTMLCanvasElement.prototype.getContext` (an un-stubbed call prints a jsdom "not implemented" error). Initialise test charts with an explicit width/height (`EChart`'s `initSize`) and assert on the SVG output.
12. **Baselines:** bar and area charts start at zero. A line chart of a few projected points (the waste projection) lets its value axis follow the data, padded: the line is the point of the chart, the axis labels stay visible and the table under it lists the exact values.
