# Design System

## Purpose

This document is the single source of truth for presentation decisions in **eco-metrics earth** — theming, typography, spacing, color palettes, visualization heuristics, and accessibility conventions. It is read by `@coder` before implementing a UI-bearing change, and by `@reviewer` when auditing one. It is extended (not replaced) as new decisions are made.

**This document outranks an agent's general knowledge.** Where it states a fact about this codebase, that fact wins over the usual answer for a React/Tailwind project. Where it marks something pending, that is an open question — not an invitation to decide it in passing. Library candidates and the technical traps behind them live in `docs/technical/libraries.md`; that document is research, not decisions.

## Theme Rules

- Dark mode is class-based: `apps/web/src/app/globals.css` declares `@custom-variant dark (&:where(.dark, .dark *))`, and `ThemeProvider`/a blocking inline script toggle the `dark` class on `<html>`.
- `apps/web` uses Next.js 16 (App Router), React 19, and Tailwind CSS v4. Every UI color is a **semantic color token** (see [Color Tokens](#color-tokens)): a raw custom property declared in `globals.css` with its light value on `:root` and its dark value under `.dark`, exposed through `@theme inline` as one utility per role. Components write `bg-surface text-fg`, never `bg-white dark:bg-black`.
- Pages and components (`src/app/**`, `src/components/**`) MUST NOT use Tailwind palette colors (`white`, `black`, `gray-500`, …) or arbitrary color values (`bg-[#…]`) — with or without `dark:` — except the documented exceptions below. `apps/web/__tests__/designTokens.test.ts` fails the unit suite on any violation, on a token missing its dark value, and on a token nobody uses.
- Code outside Tailwind that renders to the DOM (inline SVG styles) reads the raw variables, e.g. `fill: var(--accent)`; they switch with the theme on their own. ECharts cannot: charts and maps receive token values through the theme adapter (see [Chart rules](#chart-rules)).
- Eco-category icon components in `apps/web/src/components/icons/` are intentionally multicolor and use hardcoded fill values as part of each category's visual identity; per the `light-mode-styling` capability, they MUST NOT be recolored or tinted per theme. Any contrast fix must add separation (e.g. drop-shadow, border, background highlight) without altering the SVG's own colors.
- Brand raster assets use black `#000000` (the manifest `background_color`) as their opaque background: the maskable PWA icons and the apple-touch icon (logo centered, generated by `scripts/generate-pwa-icons.mjs`), and the 1200×630 social card served at `/og-image.png`, which adds the site name, tagline, a subtle `Explore the data →` call to action (emerald accent, secondary in size to the site name) and an emerald `#10b981` (`theme_color`) bottom bar. Every page's `openGraph`/`twitter` metadata is built with `apps/web/src/lib/socialMetadata.ts`, so the card is never lost to Next's shallow metadata merge.
- Category icons render with a subtle drop-shadow in light mode and a faint white glow in dark mode; large icons also sit inside a rounded container with a neutral background highlight that matches the inactive nav pills (`bg-well`). SVG fills remain unchanged. The shadow/glow pair is tokenized per size as `drop-shadow-icon-{xs,sm,lg,xl}`.

## Color Tokens

Declared in `apps/web/src/app/globals.css`. Values are Tailwind 4.3.3 palette entries written in `oklch()` (`white/N` = white at N% opacity); the two `nav-surface` values are exact conversions of `#eaecef` / `#1a1a1a`. Utility = the token name after a color prefix: `bg-surface`, `text-fg-muted`, `border-line`, `ring-focus-ring`, `ring-offset-focus-offset`, `from-nav-surface`; opacity modifiers work (`bg-surface/95`).

#### Warning tokens: contrast

Amber family, deliberately not an error red: a degraded provider is not a failure of the site. Ratios are WCAG relative-luminance contrast, computed from the `oklch()` values above (sRGB, no gamut clipping needed). Thresholds: text >= 4.5:1 on its own surface, icon >= 3:1 on every surface it sits on.

| Pair                                                | Light  | Dark    |
| --------------------------------------------------- | ------ | ------- |
| `warning-fg` on `warning-surface` (notice text)     | 8.77:1 | 13.47:1 |
| `warning-fg` on `surface`                           | 9.09:1 | 18.87:1 |
| `warning-fg` on `surface-raised` (unavailable icon) | 9.09:1 | 13.19:1 |

`warning-line` is a decorative border (1.39:1 on `warning-surface` in light, 2.10:1 in dark): the notice never relies on it, the icon and the text carry the meaning.

### Documented exceptions

- **Theme toggle lamp** (`ThemeToggle.tsx`): `text-amber-400` with an amber glow in light mode, `dark:text-gray-400 dark:drop-shadow-none` in dark mode. It is a lit/unlit state indicator rather than a role color, and the `theme-toggle` capability defines it in terms of `dark:` variants. It is the only allowlisted entry in `designTokens.test.ts`.

### Adding or changing a token

Add the light value to `:root`, the dark value to `.dark`, the `@theme inline` mapping, a consumer, and a row in the table above — in the same change. The guard test enforces the first four; the table is kept in sync by review.

## Color Palettes

Chart colors are tokens like any other color: light value on `:root`, dark value under `.dark`, in `globals.css`. There are two palettes, both read by name by the theme adapter and not mapped in `@theme inline`: the categorical `--chart-1…8` (series with no meaning of their own) and the semantic energy mix `--energy-*` (below). The first change that renders a chart adds the categorical tokens; the energy mix palette (electricity sources) is separate and semantic; the sequential ramp is added by the first change that uses it (the world map), and the divergent palette stays pending. The eight categorical tokens (`--chart-1` … `--chart-8`) are declared with the values below and are not mapped in `@theme inline`: the theme adapter (`components/charts/chartTheme.ts`) reads them by name, and `designTokens.test.ts` recognises them as used by comparing the declared `--chart-*` names with `CHART_COLOR_TOKENS`. Unlike the UI tokens they are written in hex, the form they were validated in; the theme adapter resolves any CSS color format. Both palettes were validated against the real surfaces (white in light mode, black in dark mode) with a palette validator that checks OKLCH lightness band and chroma floor, adjacent-pair separation as OKLab ΔE×100 under protanopia/deuteranopia/tritanopia simulation (target ≥ 8) and unsimulated (floor ≥ 15), and WCAG contrast against the surface.

| `energy-bio`     | Bioenergy & other renewables | green       | `#26771e` | `#11b254` |

**Validation.** Same checks as the categorical palette (OKLCH band and chroma floor, adjacent-pair OKLab ΔE×100 under protan/deutan/tritan simulation, WCAG contrast against the surface) with thresholds ΔE ≥ 8 simulated, ≥ 15 unsimulated, contrast ≥ 2.0 on white and ≥ 3.0 on black; the method and search are recorded in the archived change `openspec/changes/archive/2026-10-26-energy-sources/` (`design.md`, Decision 6).

**Results (worst adjacent pair, unsimulated / protan / deutan / tritan).** Light 23.3 / 18.0 / 15.7 / 14.3; dark 27.1 / 14.5 / 20.6 / 19.0.

**Recorded exceptions.** Coal's neutral chroma (0.02) is below the floor on purpose, and gas, wind and solar sit just above 2:1 on white (like the categorical yellow), which the legend, tooltip and tables compensate.

**Known limitation.** Only adjacent pairs are separated by colour (non-adjacent ones can be close under colour-vision deficiency), so identity is carried by the legend, tooltip and tables, never by colour alone.

### Divergent (light / dark)

Pending — define and validate it in the first change that encodes polarity with color (e.g. above/below a baseline). The global temperature page encodes polarity by line position relative to a labelled zero line, not by color, so this palette stays pending. Starting point: blue ↔ red arms with equal step counts and a neutral grey midpoint, never a hue at the midpoint.

## Typography

- Fonts and type scale follow Tailwind CSS v4's default typography utilities as currently used across `apps/web/src/app/**` and `apps/web/src/components/**`.
- No custom `@theme` font tokens are defined (the `@theme inline` block holds only color and icon-shadow tokens).

## Spacing

- Spacing follows Tailwind CSS v4's default spacing scale (the `4px`-based `space-*`/`p-*`/`m-*`/`gap-*` utilities) as currently used across the codebase. No custom spacing tokens are defined.

## Layout

- Desktop (`lg+`) sidebar (`Navbar.tsx`): fixed width `lg:w-76` (304px), matched by `lg:pl-76` on the page content offset (`layout.tsx`) — the two must move in lockstep.
- Desktop nav item rows (`NavLink.tsx`): row density `lg:py-2`, chosen so all 12 `NAV_ITEMS` fit within a typical desktop viewport height (~700px+) without scrolling.
- Vertical scroll affordance (`NavScrollContainer.tsx`): on desktop, top/bottom gradient overlays signal hidden nav items above/below the visible area, mirroring the existing horizontal affordance used by the mobile bottom bar. Both reuse the same `nav-surface` token as their horizontal counterparts (`from-nav-surface`), oriented vertically (`bg-linear-to-b` / `bg-linear-to-t`).

- Site footer (`Footer.tsx`): rendered inside the content wrapper right after the root `<main>` (`pb-20 lg:pb-0 lg:pl-76`), in normal document flow, so it inherits the mobile bottom-nav clearance and the desktop sidebar offset. A single `<footer>` (`contentinfo`, outside `<main>`) in the terminal style of the brand: the site logo with `~ eco-metrics.earth` in mono accent, a one-line tagline, one link shown as `$ cd data-sources/` (decorative `aria-hidden` prompt, accessible name "Data sources", `LINK_CLASS_NAME`), and a muted copyright/signature line under a `border-line-subtle` rule. Two columns from `sm`, stacked on mobile; tokens only (`border-line`, `text-accent`, `text-fg-secondary`, `text-fg-muted`). Mains are `min-h-screen`, so the footer sits at the end of the scroll, not in the first viewport.

### Source attribution

- `SourceAttribution` is the single "<publisher link> (<license>)" fragment for any `DataSourcePublisher`-shaped value; callers add their own lead-in ("via", "Republished by", "Some values are republished by", or "Data:" on a future chart). Names and licenses always come from the API.
- Live-provider dates on `/data-sources/` are formatted in UTC (`formatUtcDate`) and wrapped in `<time dateTime>`, so server and client render identically.
- On a cited publication, "Republished by <SourceAttribution>" sits beneath the citation; per product, "via <SourceAttribution>"; under the water-footprint table, "Some values are republished by <SourceAttribution>. <All data sources link>". The citation itself is never replaced.
- Links in running text are underlined (never color alone) and share `LINK_CLASS_NAME`: `text-accent`, `hover:text-accent-hover` and the focus-ring pattern.

## Accessibility

- Semantic HTML and descriptive titles/meta descriptions are required on every page.
- All navigable URLs use trailing-slash canonical URLs.
- Accessible markup is verified via `@axe-core/playwright` E2E coverage.
- Eco-category icons keep their hardcoded multicolor fills; contrast/separation fixes must not recolor them (see Theme Rules above).

## Presentation Stack

- **Charts and maps: Apache ECharts 6** (Apache-2.0), SVG renderer, tree-shaken imports from `echarts/core`. Chosen for its built-in interactions (legend toggling, series focus, slice selection, animated re-sorting, map zoom/pan) and for covering charts and the choropleth with one library. Evidence and the rejected alternative are in `docs/technical/libraries.md`.
- **Map geometry:** converted from TopoJSON with `topojson-client` and projected with `d3-geo` before it reaches ECharts (see rule 9 below). Still pending, to settle with the world map: the geometry source (Natural Earth vs `world-atlas`), the ISO alpha-3 ↔ numeric crosswalk, 110m vs 50m resolution, and bundled vs static-asset geometry (see `docs/technical/libraries.md` → Maps).
- **Country flags: `flag-icons` 7.6.0** (MIT, exact version pinned in `apps/web`), SVG flags selected through CSS classes (`<span class="fi fi-ar">`), never emoji — emoji flags render as two letters on Windows. Usage rules: the stylesheet (`flag-icons/css/flag-icons.min.css`) is imported only by `CountryFlag`, so it loads only with the components that show flags (route-level CSS bundling means it also ships with the other `[category]` pages, never with the home or data-sources pages); flags are decorative (`aria-hidden`) next to the country name; flags in long lists are rendered lazily (only rows that intersect the listbox viewport) because every rendered flag is a separate image request; World is shown with the monochrome `GlobeIcon`, not a flag; flags are images and are not subject to the color-token rules, but get a `ring-1 ring-line-strong` outline so pale flags stay visible on both surfaces. `GlobeIcon` lives in `components/`, not in `components/icons/`: that folder is the multicolor, one-per-category icon set.
- **Chart-scoped selector, no URL state.** A chart shows one entity at a time and its country selector and measure toggle live next to it as component state: no query string, path segment, history or storage, so the page keeps a single canonical URL. The whole dataset arrives with the page; interaction never fetches.
- **Country combobox** (`CountryCombobox`) follows the WAI-ARIA 1.2 editable combobox with list autocomplete. Keys: ArrowDown opens and moves (wrapping), ArrowUp moves (wrapping), Home/End jump to the first/last option only while the list is open, Enter selects, Escape closes (and, when already closed, restores the selected name), Tab and blur close and restore. Filtering ignores case and diacritics and ranks name prefix, then substring, then code prefix. Sizing: `text-base` on the input (no iOS zoom), `min-h-11` (44 px) input, clear button and options, `max-h-60` scrolling listbox, `max-w-sm`; the active option is shown by background plus a leading bar, the chosen one by a check glyph.
- **Anomalies are signed.** A value relative to a baseline is shown with an explicit sign and the real minus sign U+2212 (never the ASCII hyphen, which reads and wraps as a separator) in key figures, tooltips, tables and axis labels: `+0.59`, `−0.45`, `0.00` (two decimals in text, at most one on the axis), through `formatAnomaly` and `formatAnomalyAxis`, the only place a sign is produced. The sentence says "relative to the <baseline> average", which stays true for negative values.
- **A chart of values relative to a baseline draws a labelled reference line at zero** (a series `markLine`, dashed, labelled with the baseline from the payload, e.g. `1991–2020 average`). Its stroke and label colors come from the theme adapter (`referenceLine` from `fg-muted`, `referenceLabel` from `fg-secondary`), never from the option, and the value axis always includes zero.
- **A single-measure chart has no toggle.** The measure radio group exists only when there are two measures to switch (CO2: total / per capita); the global temperature explorer has the country selector alone.
- **One categorical color for the anomaly line.** Encoding the sign with color (blue/red) would be the first use of the divergent palette, which is still pending below; until it is defined and validated, the zero line carries the polarity, which also holds up for color-vision deficiency.
- **An upstream credit line is shown next to the data attribution.** When the measurements come from a producer other than the republisher and its licence asks for a credit and a disclaimer, both come from the API payload (`data.origin`) and render inside the "Data:" paragraph (the `extra` slot of `DataAttribution`), not only on `/data-sources/`.
- **Confidence band.** An interval around a line is drawn with two stacked line series (an invisible base at the lower bound and the interval width on top with a low-opacity area and no line), through `buildConfidenceBandSeries`. The band takes the main series' color from the theme palette because it shares the series name (the option never names a color; only an opacity is set), it is excluded from the tooltip, and the chart's tooltip formatter prints the interval once. Missing bounds leave a gap.
- **A reference threshold is a labelled reference line plus a sentence.** A threshold such as 1.5 °C (Paris Agreement) is drawn like the zero line (dotted so it differs from the dashed zero line without color), labelled in the chart, and explained in text: the limit refers to a long-term average, so a single year above it does not by itself breach it.
- **Below-the-fold charts render when they scroll into view** (chart rule 5): `RenderWhenVisible` serves a same-height skeleton, including in the server-rendered HTML, and mounts the lazy chart on the first intersection. The first chart of a page does not use it.
- **Each upstream origin is credited next to the chart it feeds.** `OriginCredit` renders a `DataSourceOrigin` from the API (producer, linked title, linked license, then the notice, citation and disclaimer the license asks for) inside the "Data:" paragraph; the same origins are listed on `/data-sources/` under "Data produced by".
- **Generic building blocks** for a chart page with a country selector: `CountryExplorer` (selection state, card layout, combobox; the caller supplies controls and content), `ChartPanel` (title, chart, hidden live region), `YearDataTable` (the collapsed text equivalent below) and `DataAttribution` (the "Data:" line).
- **Key figures are server-rendered text** derived from the same payload as the chart (fixed `en-US` formatting, so server and client agree), which makes them indexable and readable without JavaScript. Per-capita values that are zero or round to `0.00` read "< 0.01", never "0.00".
- **The collapsible data table (`YearDataTable`) is the text equivalent of the chart** required by chart rule 7: a `<details>` with a scrollable, keyboard-focusable region holding the selected entity's years, newest first, with an em dash for missing values.
- **Tables, key figures and controls stay HTML/React**, never drawn by ECharts: they must be indexable, reachable by screen readers and scrollable on mobile. Whether tables adopt a headless library is still pending (see `docs/technical/libraries.md` → Tables).

- **Composition charts (stacked area and donut).** They share one palette and source order, and every source is **always present in the option**, so colour follows the entity. Areas are **opaque** (`areaStyle.opacity: 1`; the default 0.7 would blend bands and break the validated colours), the percentage axis is fixed to **0–100** and a generation axis starts at 0 and fits the data (`max: null`, since `setOption` merges and would keep the 100). No band outlines and no hover emphasis: blurring the other bands of an opaque stack reads as missing colour. The axis tooltip lists only sources above zero; tables keep every source. The donut shows the selected entity's **latest year** (no year selector), labels hidden, deferred with `RenderWhenVisible`, with `PieChart` registered where it is used (`EPieChart` via `LazyPieEChart`).
- **A missing value is `null`, never zero:** a gap in a chart, an em dash in a table, "No data" in a tooltip. ECharts' generated `aria` description prints `null` as "NaN", so such a chart sets `aria.label.description` itself.
- **Tables follow the toggle.** The year table of a chart with a measure toggle shows the measure the chart shows, so it is always the text equivalent of what is visible; a small table that doubles as a donut legend (`EnergyLatestTable`) is visible rather than collapsed. Many columns use `YearDataTable`'s `wide` flag so the scroll region scrolls instead of squeezing them.
- **`MeasureToggle`** is the one radio-group toggle between measures ("Total / Per capita", "Share (%) / Generation (TWh)").

### Navigation and skeletons

- **Skeletons mean "not here yet", on the client only.** A direct visit delivers the complete page, so the HTML never holds a fallback, except for the chart area (charts render in the browser). Do not add `loading.tsx` or a `<Suspense>` around page data: React moves a boundary over about 12.8 KB out of the visible document.
- **Known content is never a skeleton.** While a category is pending, `NavigationContent` shows its real icon and `<h1>` from shared config, then `CategoryDataSkeleton` with the blocks declared in `CATEGORY_SKELETONS`. Placeholder categories have none.
- **Shape and colour.** Blocks repeat the layout of the real content down to the first chart or list, and their text is sample copy drawn as bars (`text-transparent` over `bg-well`), so it wraps like the real text at any width and nothing above the fold moves when the page arrives. Change the page's layout or copy and update `CATEGORY_SKELETONS`: `category-navigation.spec.ts` measures the drift. Fills and strokes use only `well`, `well-active` and `hover`, on `surface-raised` cards with `line-strong` borders, so they work in both themes. Animation is `motion-safe`; assistive technology gets `aria-busy` on `<main>`, and the shapes are `aria-hidden`.
- **Transition.** A 180 ms crossfade through React `<ViewTransition>`, and a thin `bg-accent-solid` bar only after 200 ms. The fixed navigation, header and theme toggle have their own `view-transition-name` above the page, or the page's snapshot would paint over them. `prefers-reduced-motion` disables both animations; without view transitions the page simply swaps.

### Degraded provider states

A provider-backed category (OWID today) can be served from a stored snapshot when its provider is down. The page decides from `meta.stale` and `meta.fetchedAt` (`lib/providerFreshness.ts`), once, on the server:

| Age of the stored data (stale only) | Shown                                      |
| ----------------------------------- | ------------------------------------------ |
| up to 7 days                        | the data, silently (no notice)             |
| over 7 and up to 30 days            | the data under the **stale notice**        |
| over 30 days, or provider `502`     | the **unavailable state** in place of data |

Defaults are `silentDays: 7` and `noticeDays: 30` (`DEFAULT_FRESHNESS_THRESHOLDS`); a category may override them with `provider.freshness` in its registry entry (`defineProviderCategoryPage`). A payload without `stale: true` is always fresh, whatever its age.

- **Stale notice** (`StaleDataNotice`): a banner directly above the section content, `warning-surface` background, `warning-line` border, `warning-fg` text and a decorative `WarningIcon`. Copy: "{Provider} is currently unreachable. Showing the copy we retrieved on {date}." with the date through `formatUtcDate` in a `<time dateTime>` and the provider from `meta.source.provider`. `role="status"` (informational, never `alert`), no controls.
- **Unavailable state** (`DataUnavailable`): replaces only the section content; the common header (icon and `<h1>`) stays and, when `meta` is known, so does the source attribution (`DataAttribution`). Neutral panel (`surface-raised`, `line-strong`, `fg`, `fg-body`) with the `WarningIcon` in `warning-fg`, not error red. `<h2>` "Data temporarily unavailable", body "We couldn't reach {Provider} to load this data. We're keeping an eye on it and it should be back soon.", and "Last retrieved from {Provider}: {date}" only when a snapshot date is known. `role="status"`, not `alert`; **no retry button**: ISR retries server-side, so a client control would only suggest an action that does nothing. The provider name comes from `meta.source.provider` when `meta` exists, otherwise from the registry entry (a `502` carries no `meta`).
- Both are tokens-only (no palette utilities) and are covered by role/semantics unit tests; axe cannot reach them in E2E because the OWID fixture server has no failure mode.

### Chart rules

1. **Colors come only from an ECharts theme built from the tokens.** ECharts parses neither `var(--x)` nor `oklch()` — a `var()` color even makes elements vanish on hover ([apache/echarts#19743](https://github.com/apache/echarts/issues/19743)) — so a shared adapter reads the tokens with `getComputedStyle`, resolves each one to `rgba()` by painting it into a 1×1 canvas and reading the pixel back, builds the ECharts theme (palette, axes, tooltip, legend, map fills) and re-applies it with `setTheme()` whenever the `dark` class on `<html>` changes. Chart options never name a color.
2. **One shared wrapper component** owns the instance: `init` with the SVG renderer, resize on a `ResizeObserver`, `dispose` on unmount. It must call `setOption` before `setTheme`: `setTheme` is a no-op until the chart holds an option. No `echarts-for-react`.
3. **Register modules where they are used.** The shared setup registers what every chart page needs (line, grid, tooltip, legend, aria, mark line, SVG renderer; bar registers where first used and the pie is registered by its own lazy entry, `EPieChart`, loaded through `LazyPieEChart`); heavier features (map, visualMap) register in the component that uses them, so they never ship to pages without them. Never the canvas renderer.
4. **Load charts lazily.** ECharts renders in the browser only. Chart components come from `lazyChart`, which imports the chunk on demand on the client and draws at once when it is already loaded (`next/dynamic` would add a Suspense boundary that delays the first chart). The page itself stays a Server Component, and `ChartSkeleton` holds the chart's height and shape (`series` or `donut`), so nothing shifts when the chart arrives. The entry animation lasts 300 ms, so a chart never feels slower than its data.
5. **Keep pages light.** A static ECharts page with line + bar + pie adds ~220 KB gzipped of JS (deferred by rule 4), and four charts at once block the main thread for ~1.8 s on a throttled mobile profile. Keep few charts per page; when a page carries several, render those below the fold only when they scroll into view (`RenderWhenVisible`). The energy sources page is the example: two charts (stacked area and donut), the donut deferred.
6. **Mobile-safe defaults** in every option: `legend.type: 'scroll'`, `tooltip.confine: true`, `axisLabel.hideOverlap: true`, truncated category labels.
7. **Accessibility:** enable `aria` (ECharts generates a description, which prints `null` as "NaN": a chart that can hold `null` sets `aria.label.description` itself), but ECharts offers no keyboard navigation inside a chart — every chart is paired with a table or a text equivalent of its data, and multi-series charts always show a legend.
8. **SEO:** a chart's SVG is not indexable content. Key figures go in server-rendered text, plus the data table and structured data where it fits. A page whose content is a dataset declares it once as a schema.org `Dataset` in JSON-LD (rendered with `JsonLd`, built from the page's own payload), never one block per chart.
9. **Maps:** project the GeoJSON with `d3-geo` (Equal Earth) before `registerMap`, otherwise countries crossing the antimeridian (Russia, Fiji) smear across the map; then set on the `map` series `aspectScale: 1`, `showLegendSymbol: false`, and all four of `left`, `right`, `top`, `bottom` so the whole world fits the container.
10. **Unit tests (jsdom):** `echarts` and `zrender` ship as ESM only, so `jest.config.cjs` is an async function that adds both to the `transformIgnorePatterns` allowlist `next/jest` generates; jsdom has no canvas, which ECharts uses to measure label text even under the SVG renderer, so `jest.setup.ts` injects an approximate `measureText` through zrender's platform module (imported alone, so tests that render no chart stay fast); the token adapter needs a stubbed `HTMLCanvasElement.prototype.getContext` (an un-stubbed call prints a jsdom "not implemented" error). Initialise test charts with an explicit width/height (`EChart`'s `initSize`) and assert on the SVG output.
